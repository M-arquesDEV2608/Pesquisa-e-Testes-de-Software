1. Pesquisa sobre Testes de Software

Tudo o que a gente pesquisou sobre a matéria:

O que são testes e pra que servem?

É avaliar o sistema pra checar se ele funciona sem erros antes de entregar. Serve pra garantir a qualidade e evitar bugs em produção.

Exemplo: Testar se o saldo do banco atualiza após um Pix.

Testes Funcionais

Avaliam se as funções do sistema atendem ao comportamento esperado pelo usuário.

Exemplo: Clicar em comprar e ir para o pagamento.

Testes de Regressão

Validam se alterações recentes no código não quebraram recursos que já funcionavam.

Exemplo: Testar login após mudar a cor da tela.

Testes Unitários

Verificam o menor componente isolado do código (como uma função ou método).

Exemplo: Testar função que calcula frete por peso.

Testes de Integração

Analisam a comunicação correta entre módulos, APIs ou sistemas diferentes.

Exemplo: Testar o carrinho com a API do cartão.

Caixa-Preta vs Caixa-Branca

Caixa-Preta: Testa só entradas e saídas sem ver o código.
Caixa-Branca: Analisa a estrutura interna e códigos (`if/else`).

Esta seção de pesquisa está organizada dentro de um .container padrão.

2. Casos de Teste Definidos

CT01 – Login com dados corretos

O que faz: Inserir e-mail e senha cadastrados.
Resultado esperado: O usuário deve entrar no sistema.

CT02 – Login com senha incorreta

O que faz: Inserir senha errada.
Resultado esperado: O sistema deve informar que os dados estão incorretos.

CT03 – Adicionar produto disponível

O que faz: Clicar em comprar um item em estoque.
Resultado esperado: O produto deve aparecer listado no carrinho.

CT04 – Tentar produto esgotado

O que faz: Tentar comprar item sem estoque.
Resultado esperado: O sistema deve impedir a adição e avisar que esgotou.

3. Resultados da Execução dos Testes

O que aconteceu de verdade quando rodamos os testes na aplicação:

Caso de Teste O que foi testado Resultado Obtido Status
CT01 Login com dados corretos Usuário acessou a página inicial com sucesso. Aprovado
CT02 Login com senha incorreta Exibiu mensagem "E-mail ou senha inválidos". Aprovado
CT03 Adicionar produto normal O produto foi pro carrinho, mas o preço dobrou sozinho (bug). Reprovado
CT04 Comprar produto esgotado O botão continuou clicável e deixou colocar o item sem estoque. Reprovado
Esta tabela utiliza a classe .container-sm para centralizar em telas menores.

4. Problemas Encontrados (BUGS) e Correções

Bug 1: Preço duplicado no Carrinho (CT03)

Problema: O código tava multiplicando o preço por dois sozinho na soma.

Correção: Ajustar a função no JavaScript para multiplicar o preço apenas pela quantidade informada.

Bug 2: Botão ativo sem estoque (CT04)

Problema: A validação de estoque não estava ligada ao botão de compra.

Correção: Inserir um `if` para desativar o botão e mostrar "Esgotado" se o estoque for zero.
